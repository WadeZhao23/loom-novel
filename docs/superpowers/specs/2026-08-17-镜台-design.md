# 镜台 · 设计

> 目标一句话:**把「它有多懂你」从散在各处的文件,变成看得见、会长大的一屏。**
>
> 日期:2026-08-17 · 前置:P3 自进化链已合入(948 测试绿) · 落点:与「脉络」平级的独立入口

## 1. 为什么是现在

Loom 最独特的资产不是「AI 帮你写一章」,是**「它在变成你」**。市面上任何工具都能生成一章;
没有一个能给你看**「我对你的理解」**、还让你改它。

这个资产今天**完全不可见**:

| 东西 | 现在住哪 | 作者看得到吗 |
|---|---|---|
| 写作指纹 | `外置大脑/写作指纹.md` | 一个文件 |
| 人格增补 | `agents/<角色>.md` 的 `## 个人增补` | 一段文本 |
| 「越写越像你」的证据 | **没有** | 没有 |

作者点「学这章的手改」,然后没有下文。

**镜台补的就是这一环**:把三样东西聚成一屏,核心是一条曲线——**每章手改量随时间下降**。
「第 1 章你改了 28%,第 20 章改了 5%」比任何文案都有说服力,而数据**已经在算了**。

### 一个交叉点

这条曲线同时是两样东西:

- **产品的英雄指标**——它就是「越写越像你」的证明
- **自进化的闭环护栏**——增补学歪了,手改量会涨

同一个数,既讲价值又拦事故。这种交叉点少见,所以先做它。

> 本期**只做只读投影**,不做自动护栏(检测到手改量上升就提示撤销)。
> 理由:「手改变多 = 学歪了」这个因果不牢靠(作者可能只是这一章想多改),自动提示会误报。
> 曲线摆出来让作者自己看见,已经拿到大部分价值;护栏要的数据全在这一期里,随时能加。

## 2. 已拍板的决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | **只做只读投影**,不做自动护栏、不做规则卡 | 见上;B/C 要的数据全在 A 里 |
| 2 | 曲线画**两条**:改写率 + 增删率 | 两条线意义不同,且拆分已经算好了(§3) |
| 3 | **独立入口**,与「脉络」平级 | 脉络=故事的投影,镜台=你的投影;做成平级才有分量,而「资产不可见」正是要解的问题 |
| 4 | **现算,不缓存** | 缓存引入第二真相(作者随时可以再手改),而 40 章句级 diff 是毫秒级——缓存换来的性能等于零 |
| 5 | 中文词条叫**镜台** | 书房隐喻,与「书房伙伴」「脉络」同一个空间 |

## 3. 算什么

对每一个**learn 过的**章 `n`:读 `正文/第N章.md`(手改后)与 `正文/.原稿/第N章.md`(AI 稿),
两边都 `strip_title`,句级切分后跑 `SequenceMatcher`:

| 指标 | 来源 | 产品含义 | 对应的可进化对象 |
|---|---|---|---|
| **改写率** | `replace` 块**取 AI 侧**句数 ÷ AI 稿总句数 | 它**像不像**你(voice) | 写作指纹 |
| **增删率** | (`delete` 的 AI 侧句数 + `insert` 的作者侧句数) ÷ AI 稿总句数 | 它**懂不懂**你要什么(what) | 外置大脑 / 人格增补 |

两处口径写死,避免实现时二义:

- **改写率取 AI 侧**(`ai[i1:i2]` 的长度,不是 `you[j1:j2]`)。`replace` 块两侧句数可以不等
  (作者把一句拆成两句)。分子分母同侧,这个数才读得懂:「**这份 AI 稿有多少比例被你改写了**」。
- **增删率的分子跨两侧**(删的算 AI 侧、加的算作者侧),分母仍是 AI 稿总句数。
  它量的是「**相对这份 AI 稿,你做了多少句的增删动作**」,所以理论上可以 >1
  (整章推翻重写时)——这是对的,不要钳到 1。

这两类正是 `fingerprint._aligned_signal` 已经在拆的两类(ADR 0005 的句级对齐),
而它们恰好对上产品本来的 voice/what 两轴。

### 句级对齐必须共用一份

`fingerprint.py` 是句切的家(`_segment` + `_aligned_signal`)。在那里导出

```python
align_stats(ai: str, edited: str) -> {"改写句数": int, "增删句数": int, "总句数": int}
```

`_aligned_signal` 与 `mirror` **共用它**。绝不建第二个句级对齐——否则曲线和指纹学到的东西
会对不上,而这一屏的全部说服力就来自「它和 learn 学的是同一件事」。

依赖方向单向:`mirror → fingerprint`,不反向,无环。

### 一个诚实的边界:只算 learn 过的章

没 learn 的章手改率是 0,但那个 0 的意思是「**还没看**」,不是「不用改」。
摆进曲线会让指标虚假地好看——而这是要当英雄指标用的东西,**虚高一次就再也不可信了**。

`learn` 是作者说「这章我过完了」的那个动作,用它当边界最诚实。
导入章(无 `.原稿` 快照)同理排除。

## 4. 形状与接口

### 模块

```
loom/mirror.py     纯计算投影:不调模型、不写盘、不打分(照 studio.py)
  依赖 → paths / state / chaptertext.strip_title / persona / fingerprint
  不依赖 → backends(不发任何请求)
```

### 返回形状(一次给全屏)

```python
mirror(root) -> {
  "曲线": [{"章": 3, "改写率": 0.28, "增删率": 0.11, "字数": 1142}, ...],
  "指纹": {"来源": "sample", "规则数": 23,
           "anchor": ["风停了。他把刀收回鞘里,没回头。", ...]},
  "人格": [{"角色": "大纲师", "增补条数": 9, "增补": ["- ...", ...]}],
  "覆盖": {"已学": 12, "有稿": 20, "总章": 22},
}
```

`覆盖` 是给作者的诚实交代:曲线只画了 12 章,因为另外 8 章还没 learn。

### 接口

- `GET /api/mirror?root=` —— 照 `/api/studio` 同一形状、同一错误包装
- `loom status` 加一行摘要(最近若干章的两个率);**这行也是开发期自验的手段**

### 落点

侧栏新入口 → 自己的弹层。弹层内三块:

1. **曲线**(主):两条线,横轴章号
2. **指纹**:规则条数 + anchor 原句
3. **人格增补**:按角色分组

**空态是个机会**:一章都没 learn 时,这屏说「写一章、手改、点『学这章的手改』,这条线就开始长了」
——顺手把产品的核心循环教一遍。

## 5. 错误处理

照 `studio.py` 的附赠类纪律,**镜台绝不抛**:

| 情况 | 行为 |
|---|---|
| 导入章(无 `.原稿` 快照) | 跳过该章 |
| 文件读不了(权限/编码坏) | 跳过该章 |
| `.loom_state.json` 坏了 | `load_state` 已兜底 → 曲线空,不炸 |
| `agents/<角色>.md` 缺失 | 该人格不进列表 |
| 写作指纹文件缺失 | 指纹块为空 |

任何一块坏掉,弹层照样打得开、其余块照常显示。镜台不在出稿路径上(独立端点),
风险面比 `studio` 还小;`loom status` 那行摘要靠近出稿路径,整段吞异常。

## 6. 红线

1. **不调模型、不写盘、不打分** —— 同 `studio.py`;markdown 仍是唯一真相,这里只是「读法」
2. **只算 learn 过的章** —— 诚实边界,见 §3
3. **句级对齐共用一份** —— 不建第二个
4. **标题不进** —— 改标题不算手改(ADR 0009)

## 7. 测试

全部先红后绿:

| 测什么 | 判据 |
|---|---|
| 比率算得对 | AI 10 句、改写 3 句 → 改写率 0.3 / 增删率 0 |
| 两类分得开 | 作者加 2 句 → 增删率 0.2 / 改写率 0 |
| 诚实边界 | 改过但没 learn 的章 **不进**曲线 |
| 导入章排除 | 无 `.原稿` → 不进曲线 |
| 标题不算手改 | 只改首行 H1 → 两个率都是 0 |
| **共用性** | `_aligned_signal` 与镜台用的是**同一个函数**(`is` 断言) |
| 覆盖三数对得上 | 已学 / 有稿 / 总章 |
| 空书不炸 | 结构完整、各块为空 |
| 缺 agents 不炸 | 该人格不列,其余照常 |

「共用性」那条用 `is` 断言(同 `agents._scene_range is artifacts.scene_range` 的做法):
不是「两边算得一样」,是「**两边就是同一个对象**」——防漂最硬的形式。

## 8. 分两阶段做

| 阶段 | 内容 | 验收 |
|---|---|---|
| **一期(本 spec)** | `mirror.py` + `align_stats` 抽公用 + `/api/mirror` + `loom status` 摘要 | 全量测试绿(基线 948);样例书上 `loom status` 打出真实数字 |
| **二期** | 侧栏入口 + 弹层三块 + 曲线画法 | 界面里能看到那条线 |

**为什么拆**:我这次会话一直在引擎里,**没打开过 UI**。一期的每一条我都能自己写测试、自己真机验;
二期的交互细节(入口摆哪、弹层布局、图表怎么画)你比我清楚,而且 `app.js` 已经 3216 行,
盲改的风险不小。一期做完,二期要的数据全都齐了,接不接、怎么接由你定。

## 9. 不在本期范围

| 不做 | 为什么 |
|---|---|
| 自动护栏(手改量上升 → 提示撤销) | 因果不牢靠,会误报;数据已备好,随时能加 |
| refine 规则做成可开关/可追溯的卡 | 要改 persona 的存储形态,范围翻倍 |
| 跨书视图(这个作者的全部书) | 作用域决策是「默认每书 + 显式继承」,跨书聚合另说 |
| 前端(侧栏入口 / 弹层 / 图表) | 归二期,见 §8 |
