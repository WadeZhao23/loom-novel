# Loom Continual Harness · 设计(0.5.0)

> 目标一句话:**把已经在写作指纹上验证过的 learn 纪律,从一个可进化对象推广到四个;同时把五道固定工序换成一个能回头的写作 agent。**
>
> 日期:2026-08-16 · 起点:v0.4.4(843 测试全绿) · 外部参照:DeepSeek Harness(dsh)、Prime Agent

---

## 1. 为什么是现在

### 1.1 两个外部参照,各取一半

**DeepSeek Harness**(2026-08-13,MIT,建在 Cordis 上):「一切皆插件」——模型/工具/skills/会话/沙箱/存储/循环/调度/UI 全部可换,agent 循环拆成可拦截事件流。

**Prime Agent**(PrimeIntellect,2026-08-05,MIT):两个抽象——**RLM**(context 当变量、子 agent 当函数调用,跑在常驻 IPython REPL)+ **Continual Harness**(提示词/skills/记忆/子 agent 都是可 CRUD 的持久状态);`/refine` 回看最近约 30 轮轨迹做**有证据支撑的小步增量更新,绝不重写基座提示词**。

**Loom 取什么、不取什么:**

| 参照 | 取 | 不取 | 为什么 |
|---|---|---|---|
| dsh | 插件形态、可拦截事件流、可回放轨迹 | **运行时本身** | `deepseek-harness-runtime-bin` 只出 linux-x64 / linux-arm64 / **macOS arm64**——没有 Windows、没有 Intel Mac,而 Loom 出 macOS+Windows 桌面端;且 Python SDK 只有 turn 级 `RunResult`,**无 token 级流式**,Loom 四处流式安全闸(哨兵过滤/协议行拦截/思考灰字/边写边看)会全部退化;版本 `0.1.0rc6`,README 明示破坏性变更 |
| Prime Agent | Continual Harness、`/refine` 的增量纪律、skills 可固化 | **IPython REPL** | 给作者的 `.app` 塞一个能执行任意 Python 的 REPL,直接破「稿子不离机」的信任面;且 Loom 的一章 prompt 从来不是 100k token 的场面,**没有 RLM 要解决的那个问题** |

> 顺带避坑:PyPI 上裸名 `deepseek-harness` 是第三方包,官方是 `deepseek-harness-sdk`。

### 1.2 Loom 早就发明过 `/refine`,只是只用在一个对象上

`fingerprint._LEARN_SYSTEM`(`loom/fingerprint.py:42`)的纪律与 Prime Agent `/refine` 逐条同构:

- 增量并入,**不推倒重写**
- 既有规则**默认一条不删**,只在①追加新观察 ②本次证据直接矛盾 ③合并近义 三种情况下动
- anchor 例句**只增不减、逐字保留**
- 落盘前留可撤销快照(`.指纹历史/`),软闸只提示不阻断

差别只有一个:**Loom 只让写作指纹进化,Prime Agent 让四类东西进化。**

所以本设计不是推倒重来,是**把验证过的纪律推广开**。

### 1.3 Loom 比参照物强的那一点(值得单独留档)

Prime Agent 的 `/refine` 只能让模型回看轨迹**自评**「这个决策本可以更好」——因为没有人在旁边逐字改它的输出。

**但 Loom 的作者每一章都在手改。** 那是 ground truth,不是评价。

于是 refine 不需要问「本可以更好吗」,只需要看「**作者实际改成了什么**」。这一步同时:

- 比自评可靠(有人类信号,不是模型照镜子)
- 顺带守住 [ADR 0002](../../adr/0002-fingerprint-purpose-and-division.md)/[0006](../../adr/0006-quality-gates-issue-driven-non-blocking.md) 的**不打分**红线——全程没有一个分数

## 2. 已拍板的决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | dsh **取形不取身**,零依赖 | 无 Windows/Intel Mac 轮子 + 无 token 级流式 + rc 破坏性变更(见 §1.1) |
| 2 | 参照 Prime Agent 建 **Continual Harness** | 其 `/refine` 纪律与 `_LEARN_SYSTEM` 同构,是已验证形状 |
| 3 | 四类可进化对象**默认每书 + 显式继承** | 沿用 `seed_from_inherit`(`fingerprint.py:132`)已验证范式;零跨题材污染 |
| 4 | refine **领航员提、作者点头** | 复用候选卡形态,不新建 UI 概念,守「绝不替作者做决定」 |
| 5 | 五工序**彻底 agent 化** | 换来**可回头**:今天写手写崩只能整章重跑,agent 化后可退回改细纲重来 |
| 6 | 判据用**作者手改**,不用模型自评 | Loom 有 ground truth;顺带守住不打分(见 §1.3) |
| 7 | 五个角色**降级为人格,不再是工序** | 产物名不变 → UI/README 的五个头像照旧成立,但顺序与次数由 agent 定 |

## 3. 架构:三层

```
┌─ ③ Continual Harness ── 四类可进化对象 + 统一 refine 纪律
│                          证据源 = 作者手改 + 行为事件流
├─ ② 写作 agent 循环 ───── 一个 agent、五个人格、产物提交协议
│                          护栏挂在【产物提交】上,不挂在【棒】上
└─ ① 可寻址上下文 ─────── 外置大脑/工作区/硬设定 变成按需取的只读工具
                           (不再全量拼进一个大字符串)
```

### 3.1 ① 可寻址上下文层

今天 `_build_user_prompt`(`agents.py:612`)把外置大脑 + 工作区 + 上一章 + hardfacts 全量拼成一个字符串。改成**只读工具按需取**——`partner_tools.REGISTRY` 已经在伙伴通道验证过这条路。

净效果:每次 `complete()` 的 prompt **比今天更小**,不是更大。

### 3.2 ② 写作 agent 循环

**形状照搬 `partner.run_turn`(已在 claude/codex/DeepSeek 三类后端上跑通)**:

- 每轮 = 一次 `complete()`;模型按文本协议输出「用:工具名」块
- Loom 侧执行工具、回喂、再 complete;`agent_mode=True` 解 CLI 反 agent 护栏(`backends.py:362`)
- **真实读写永远在 Loom 服务端**,模型自己没有 shell/文件能力
- 轮数上界(照 `_MAX_TOOL_ROUNDS=6` 的先例定,写章放宽)

**五个人格**:设定师 / 大纲师 / 写手 / 编辑 / 润色师 从「工序」降级为「人格」。agent 在循环里戴帽子干活,产物名不变(设定锚点/细纲/初稿/改稿/终稿)——所以 UI 五个头像照旧点亮,只是**可以重复、可以回头**。

> **这才是付这个代价的理由**:今天流水线单向,写手写崩了只能整章重跑;agent 化后它能自己退回改细纲重来。不是「因为 Prime Agent 这么做」。

### 3.3 ③ Continual Harness

见 §5。

## 4. 护栏换挂点(本设计最关键的一节)

agent 化**不丢任何一条护栏**,只把挂点从「棒」换成「**产物提交**」。产物提交是一个 Loom 侧工具,agent 绕不过去。

| 护栏 | 今天挂在 | 换到 | 变化 |
|---|---|---|---|
| 非空闸 `validate_output` | 每棒后 raise(`agents.py:773`) | 提交工具内 | **变好**:不合格不落盘 + 回喂让它重交(自愈),不再中断整章 |
| 质检 gate | 编辑棒后 | 提交「改稿」 | 语义不变;**Loom 侧强制,agent 不能选择不跑** |
| 去AI味 gate + 确定性预筛(aitell/fatigue) | 润色师后 | 提交「终稿」 | 同上 |
| 篇幅三管齐下 | `_length_hint` 按 role 分支 | 提交「细纲」的工具契约(场次预算+每场标字数) + 提交「终稿」的字数校验 | **必须挂在契约上**,不能靠 agent 自觉——字数五螺丝的教训是软话压不住篇幅 |
| 审稿留痕分离 | `_edit_stream_filter` 流式切哨兵 | 独立产物「提交留痕」 | **变好**:不再靠切字符串,留痕与改稿物理分开 |
| 硬设定逐字 | `wants_hardfacts` 注入 | 只读工具「查硬设定」 | 写手人格的提交契约里**强制先取**,防专名漂移 |
| 状态账本 | `wants_state` 注入 | 只读工具「查状态账本」 | 同上 |
| 续跑账本 | 每棒 sha + 上游签名 | **产物级**:轨迹 jsonl + 已提交产物 | 上游签名失配 → 弃轨迹重跑;比今天的签名图**更简单** |
| 伏笔悬空提醒 | 编辑棒后扫 | 提交「改稿」后 | 语义不变 |
| WYSIWYG 细纲 | `outline_wysiwyg` 旁路 | 细纲文件存在 → 「提交细纲」工具直接返回已有内容 | 语义不变 |
| 违禁词 / 超长 / 除虫 | 终稿落盘后 | 不变 | 不变 |

**红线不变**:安全攸关行为(gate 挂接、提交校验、留痕隔离)只住在**代码侧**,绝不下放到用户可编辑的 `agents/*.md`——同 `agents.py:74` 那条注释。

## 5. 四类可进化对象 + 统一 refine 纪律

### 5.1 四类对象

全部**每书一份**,跨书只能作者主动「从《XX》继承」(沿用 `seed_from_inherit` 范式)。

| 对象 | 落点 | 证据源 | 喂给谁 |
|---|---|---|---|
| 写作指纹(已有) | `外置大脑/写作指纹.md` | 手改 diff(句级对齐) | 写手、润色师人格 |
| **agent 提示词增补** | `agents/<角色>.md` 的 `## 个人增补` 区 | 你对该产物的手改 + 反复否决 | 对应人格 |
| **skills 检测器规则** | `skills/` + `DETECTORS` 注册表 | 反复复现的手删模式 | 去AI味关卡 |
| **习惯记忆** | `.进化/习惯.md` | 行为事件流(拍板/否决/改参数) | 领航员、大纲师人格 |

**轨迹与习惯记忆不进外置大脑**(进了会被人格当设定读到)。开书内点目录 `.进化/`,照 `.审稿留痕/` `.伙伴对话/` 先例:进 `loom backup`,**整个删掉书完好无损**,退回出厂行为。

### 5.2 `agents/*.md` 分两区

```markdown
## 基座
(包内模板。refine 永不碰,升级随包走)

## 个人增补
(refine 只写这里。一键清空回出厂)
```

不是新发明——复用 `[AI补充]` 物理隔离块那套已验证做法([ADR 0007](../../adr/0007-external-brain-grows-with-story.md)):只追加、绝不覆盖人写的主体。同一个形状,换个落点。

### 5.3 统一 refine 纪律(照搬 `_LEARN_SYSTEM` + `/refine`)

1. **增量并入**,不推倒重写
2. 既有条目**默认一条不删**;只在「本次证据直接矛盾」时改写那一条
3. **基座永不重写**,只动个人增补区
4. 落盘前留可撤销快照 → `.进化/历史/`
5. **不打分**——判据是「作者实际改成了什么」,不是模型评价

### 5.4 触发:领航员提、作者点头

证据攒够(跨 N 章出现同一模式)→ 领航员在对话里主动说:

> 「你连续 5 章把大纲师的四场改成三场。要不要把『这本书默认拆三场』写进大纲师的个人增补?」

作者点了才落。**复用已有的候选卡形态,不新建 UI 概念。**

## 6. 分期与验收闸

四期,一次发 0.5.0。**每期独立验收,不许带着红的测试往下走。**

| 期 | 内容 | 验收闸 | 估时 |
|---|---|---|---|
| P1 | 写作 agent 循环 + 产物提交协议 + §4 护栏全部换挂点 | 843 测试全绿(改写受影响的那批);真机跑通一章,五个头像照旧点亮 | 5–8 天 |
| P2 | 轨迹 jsonl + 产物级续跑重建 | 断点续跑真机验证:中途杀进程,重跑只补未提交产物 | 2–3 天 |

## 7. 红线(推翻架构 ≠ 推翻产品)

这四条是产品本身,不是实现习惯,**一条都不动**:

1. **绝不替作者做决定**;未拍板的一个字不进书
2. **写作指纹的学习信号只能是作者手改 diff**([ADR 0002](../../adr/0002-fingerprint-purpose-and-division.md));voice 的收敛性全靠它
3. **不打分、不硬阻断**(ADR 0002/0006)
4. **稿子不离机**;无服务器,不引入能执行任意代码的运行时

外加两条本设计新增的:

5. **轨迹永不当状态真相**——只作证据源,不读回派生任何门禁/完成度([ADR 0013](../../adr/0013-journey-orchestration-no-langgraph.md)原样成立)
6. **习惯记忆绝不喂写手人格**——写手的 voice 源只能是写作指纹 + 文风参考,否则「像你」被稀释

## 9. 未决 / 风险

1. **成本与轮数**:今天一章 = 5 次调用 + gate。自主循环可能翻倍。需要在 P1 就定死轮数上界 + 真机量一次实际调用数,别等用户账单说话。
2. **前端进度渲染**:`events.pipeline_start(chapter, roles)` 现在发的是固定五棒列表(`agents.py:665`),webui 用它画 pill 进度条。agent 化后棒次动态,进度条形态要重设计。
3. **evals 棒级归因**:`evals/stepgraders.py` 按棒取产物。产物名不变的话 grader 主体可留,但**基线必须重跑一遍**,这笔时间在 P4 里。
4. **README 门面**:「流水线上的五个人」+ 那张 mermaid 单向流程图,agent 化后叙事要改成「五个人格,可以回头」。产品门面变更,不只是技术改动。
